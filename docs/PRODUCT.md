# AutoReadPaper 产品方案

状态：2026-11-03 的设计基线。首版本地应用现已实现；实际支持范围、运行方法和验证边界以 README.md 为准。本文中后续阶段与验收目标不代表均已完成。

## 1. 产品目标

用户配置研究主题后，系统持续检索相关论文，对新发现的相关论文自动阅读，并将图文总结长期整理归档。用户能快速判断是否值得细读，也能追溯总结的依据。

核心价值是持续积累一个围绕研究主题组织的阅读库。单篇总结、每日新论文和历史资料应连成同一条使用路径。

用户已确认本地部署优先，后续再评估兼容 Dot 云端运行。首版面向个人研究者、中文阅读优先仍为设计提案，小团队协作作为后续扩展。

## 2. 主题如何定义

主题同时包含自然语言描述和可编辑检索条件。自然语言用于表达关注点，检索条件用于控制实际发现范围。

| 配置项 | 示例或行为 |
| --- | --- |
| 名称 | 视觉语言导航 |
| 描述 | 关注机器人如何根据自然语言指令和视觉观测完成导航 |
| 包含词与别名 | vision-language navigation、VLN、instruction following navigation |
| 排除条件 | 仅关注自动驾驶车辆的工作；保留人工恢复入口 |
| 重点问题 | 输入输出是什么？是否闭环？是否有真实机器人实验？ |
| 检索来源 | 首版 arXiv，可选类别与检索表达式 |
| 首次回溯 | 默认提案：最近 30 天，开始前可预览候选量 |
| 运行频率 | 默认提案：每天 09:00，时区 Asia/Shanghai |
| 阅读预算 | 默认提案：每主题每天最多新读 5 篇；另设全局额度 |
| 更新策略 | 新版本是否重读；默认记录更新，有预算时生成新总结 |

系统可建议英文关键词、同义词和检索表达式，保存前让用户看到实际查询与样例结果。主题不限于某一学科，上例仅用于说明。

主题可暂停、修改、归档。修改产生配置版本，历史命中理由保留；新配置可触发一次显式回溯。删除主题默认解除归类，不删除共享论文或用户笔记。

### 配置交互：优先选择，减少填写

用户已明确：能通过下拉列表提供的配置项优先使用下拉列表，让操作简单。下表中的选项与默认值为具体设计提案；不要求用户填写配置文件或检索语法。

| 配置项 | 控件与选项 | 默认行为 |
| --- | --- | --- |
| 研究主题 | 可搜索的主题模板下拉框，含“自定义主题” | 选择模板后填入可编辑名称、描述和建议关键词；不自动订阅 |
| 检索来源 | 来源多选下拉框 | 首版仅 arXiv 可选，未来未接入来源不作为可用选项 |
| 学科类别 | 可搜索多选下拉框，显示中文名称与来源类别代码 | 不限类别；与已选来源联动 |
| 检索频率 | 每天／每周／仅手动 | 每天；选每周后显示星期下拉框 |
| 执行时间与时区 | 时间选择器、可搜索时区下拉框 | 09:00、Asia/Shanghai；显示下次执行时间 |
| 首次回溯 | 最近 7 天／30 天／90 天／自定义日期范围 | 最近 30 天；选自定义才显示日期选择器 |
| 每主题每日阅读上限 | 1／3／5／10／20 篇／自定义 | 5 篇；自定义时才显示正整数输入框 |
| 论文更新策略 | 自动重读新版本／仅记录更新，手动重读 | 自动重读，仍服从阅读额度 |
| 总结语言 | 中文／英文 | 中文，保留原文标题和关键术语 |
| 模型连接与模型 | 已配置连接下拉框、对应可用模型下拉框 | 使用全局默认；未配置时提供连接设置入口 |
| 包含词、排除词与重点问题 | 可搜索多选建议，并允许添加自定义标签或问题 | 从主题模板给出建议，允许删除或修改 |

名称与研究描述保留文本输入。密钥使用密码输入框，目录使用目录选择器，启停使用开关；这些控件按实际操作选择。模型连接的自定义地址和模型标识放入高级设置，无法列举模型时允许手动填写。

新建主题默认只展开主题选择／描述、频率和每日阅读上限；其他配置折叠在高级设置，并展示当前默认值摘要。模型连接在全局配置一次，主题默认继承。费用额度提供带币种的数值输入，避免用未经测量的“便宜／昂贵”档位代替实际额度。

下拉选项使用清晰名称，长列表支持搜索，多选结果显示为可删除标签，支持键盘操作和明确标签。自定义值保存后重新打开时正确回显；修改关联选项导致旧值不可用时给出提示，不静默换成其他选项。保存前展示可读配置摘要和实际检索样例，高级检索表达式仅在高级设置中编辑。

## 3. 完整使用流程

1. **创建主题**：填写描述，预览检索结果，调整包含与排除条件，设置频率和预算。
2. **定期发现**：获取元数据，区分首次发现、既有论文、已有论文的新版本。
3. **相关性筛选**：规则粗筛，再根据摘要判断相关性，给出理由；不确定的候选进入待确认区。
4. **自动阅读**：按优先级和额度获取全文、解析正文与图表、生成总结并检查来源。
5. **归档浏览**：在主题信息流查看新增总结，打开论文详情，核对原文、收藏或写笔记。
6. **后续积累**：处理论文版本更新、补齐失败任务、搜索历史总结、导出资料。

同一篇论文可以属于多个主题，通用的全文阅读结果共享；各主题的相关性说明分别保存。超出当日额度的相关论文排队等待，不直接丢弃。

## 4. 每篇论文的阅读报告

采用两层阅读深度：列表上的速览帮助选择；详情里的结构化报告帮助理解。默认中文，保留标题与关键术语原文。

| 模块 | 要回答的问题 |
| --- | --- |
| 基本信息 | 标题、作者、日期、来源、版本、原文链接、阅读范围是什么？ |
| 一句话结论与速览 | 解决什么问题，主要方法是什么，作者报告了什么结果？ |
| 问题与背景 | 既有方法的哪项限制促成了这项工作？ |
| 方法详解 | 输入输出、模块关系、训练与推理流程、关键公式如何工作？ |
| 贡献与证据 | 作者声称的贡献是什么，对应依据在哪里？ |
| 实验解读 | 数据、任务、对照方法、指标、实验条件与结果是什么？ |
| 关键图表 | 方法图或关键结果图表达什么，怎样与正文对应？ |
| 局限与待确认项 | 作者承认的局限、系统的分析、缺失证据分别是什么？ |
| 与主题的关系 | 为什么值得这个主题的使用者关注，可以借鉴什么？ |
| 延伸入口 | 原文中出现的代码、项目页、数据及相关工作链接 |

图文总结的首版形式是“原论文关键图表 + 中文解释 + 原文定位”。可选自动生成的方法示意图放在后续版本，并标注为系统绘制。

关键图优先选择方法总览、流程和主要实验结果；数量按论文内容决定，不强凑。保留图号、图注、PDF 页序与来源链接。定位不可靠时展示整页预览并标记待核对，避免裁错图仍给出确定解释。

报告必须遵循以下证据规则：

- 关键结论和实验数字关联原文章节、页序或图表；缺少定位时降低报告完整度。
- “作者报告”“系统分析”“待确认”分别呈现；仿真、真实机器人和其他评测环境分别注明。
- 全文缺失时只生成摘要级速览；解析部分缺失时标注遗漏范围。下载成功本身不代表读完。
- 不将项目链接的存在写成代码已开源，不将摘要中的宣传写成独立验证结论。
- 自动检查通过表示格式与引用位置等检查通过，准确性仍需通过抽查评估。

## 5. 浏览体验与页面

| 页面 | 核心内容与操作 |
| --- | --- |
| 首页／更新流 | 各主题新论文、已完成总结、待阅读与失败项；区分新论文和版本更新 |
| 主题详情 | 描述与检索条件、论文时间线、相关性理由、预算、暂停和手动检索 |
| 论文库 | 按主题、日期、作者、来源、阅读范围、收藏和已读状态筛选与搜索 |
| 论文详情 | 上方速览，下方方法、图表和实验；原文入口、版本切换、笔记与导出 |
| 任务与运行记录 | 最近检查时间、下次执行、扫描是否完整、失败原因、重试与额度 |
| 设置 | 模型连接、部署时区、全局预算、存储和导出配置 |

论文卡片展示标题、日期、主题、简短结论、阅读范围和用户阅读状态。用户的“未读／已读”与系统的“待处理／生成完成”是两个独立状态。

详情页优先给用户研究内容；任务标识、模型版本等技术信息放入可展开的来源与运行详情。正文支持章节导航，图表可放大，引用可打开对应 PDF 页。

首版站内更新流承担通知功能。用户未配置外部通知渠道时，不发送邮件或其他消息。

## 6. 首版边界与后续能力

| 阶段 | 交付能力 |
| --- | --- |
| v0.1 必须具备 | 多主题配置、arXiv 检索、arXiv 链接与本地 PDF 导入、去重与版本识别、全文图文阅读、持久任务、归档搜索、收藏笔记、Markdown 与图片导出 |
| v0.2 候选 | 更多论文源、项目页辅助阅读、跨论文对比、主题周报、用户反馈改善筛选 |
| 后续按需求 | 问答与语义搜索、多用户共享、外部通知、自动绘制解释图 |

首版不承担代码复现或实验验证。报告可以说明作者的实验与实现信息，但不能标成系统已复现。

主题内容与论文检索先形成闭环，博客、新闻和一般网页后续以独立资料类型接入，避免与论文混为同一种证据。

## 7. 自动运行的产品约定

- 本地服务停止时不会继续检索；恢复后记录离线区间并补检。若需要全天自动运行，应部署到持续在线的主机。
- 首版浏览界面、调度、任务执行和档案存储均以本地运行为基线。模型仍可通过配置使用远程服务；本地部署不等于必须本地运行模型。Dot 云端兼容不作为首版验收条件，未来验证后再增加运行方式选项。
- 进程重启保留主题、任务、论文和笔记；恢复未完成任务，不从头重读全部存量。
- 来源故障展示“本次检索失败”；返回零条且扫描完整才显示“未发现匹配论文”。
- 每次检索记录查询、时间区间、页数、候选数及截断情况，不承诺覆盖整个互联网。
- 额度不足时显示等待原因与恢复时间；未配置模型时可发现和归档元数据，阅读任务显示待配置。
- 论文更新生成独立的版本记录和总结，不覆盖旧报告及人工笔记。

## 8. 验收方案

以下为实施后的验收计划，当前尚未执行。

1. **完整流程**：创建主题，手动与定时触发检索，完成一篇全文图文报告，随后能在主题和论文库中找到并导出。
2. **重复与版本**：连续运行两次不重复建档；同一论文的新版本独立留存；两个主题命中同一版本时复用通用阅读结果。
3. **恢复与预算**：在下载、模型请求及导出阶段中断后重启，任务可恢复；全局与主题额度生效，不重复占用同一份阅读额度。
4. **异常与降级**：覆盖网络超时、限流、缺少全文、损坏 PDF、图号匹配错误、长文截断和无模型配置，界面准确展示状态。
5. **可用性**：能搜索中文与英文术语，打开对应原文页，保存笔记，切换版本并导出可离线阅读的图文档案。
   配置流程须验证：通过预设选择完成主题创建，无需手写检索表达式；每周频率、来源与模型联动正确；自定义值保存回显、无可用模型提示和键盘选择可用。
6. **质量评审**：固定一组约 20 篇涵盖双栏、图表密集、长附录及抽取困难案例的公开论文；人工核对关键结论、数字、引用和图文对应，记录每项错误及修订结果。

相关性质量另用含相关、边界和不相关论文的固定标注集评估，报告精确率与召回率。质量集、模型及提示词版本固定后再比较；不以报告数量或文字流畅程度代替准确性。

## 9. 待确定事项

- 首个主题与关注问题；主题示例不代表已创建订阅。
- 模型服务、是否可将全文发送至外部模型、单日阅读数量和费用额度。
- 本地运行环境与启动方式；首版默认单用户，Dot 云端接入后续另行评估。

这些事项决定实际接入配置；当前无需创建外部账号、部署服务或启动定时检索。
